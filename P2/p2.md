# 1. The design problem, audience and value (Gabby)
Who Exactly: 

    Role: This project would benefit music-loving university students who want to get back into reading through a fun, personality-analyzation-style experience. It targets students comfortable with digital technology who want short, personalized poetry recpmmendations based on their recent music taste.

    Situation: The mindset of a user who opens this app would look like someone who listens to a lot of music and wants to find low-pressure, enjoyable ways to feel productive- such as reading; someone with recent motivation to start reading again, but doesn't want to immediately jump into long novels- rather they're looking for short reads to incorporate into their daily routine. 

    Trying to get done: They (users) want to see their current music taste analyzed with a few words, then receive a list of poems that match with those words.  

Why would they use this instead of what exists?:
There are a lot of existing apps that analyze users' listening history and attach their data to fun personality results, and there are a lot of different resources online to get recommended poetry picks, however there aren't any apps that I've found yet that do both in one go, causing extra work for any music fans trying to find poems that match with their current listening vibes. In contrast to what already exists, this app combines listening history analysis together with poetry recommendations, helping users easily find poems that feel personally relevant to their music taste. 

# 2. Depth Item (Gabby)
Our Depth Item is an AI step with a human check. 

Adding AI into our project adds an additional appeal to the audience by allowing their listening data to be further looked at (analyzed) in order to  recieve a unique descriptive word for their music taste. (Which will be used to find poems catered towards the user)

This new depth item piece will require an LLM call.

# 4. Data Sources (Flora)
## Source 1: PoetryDB
- Docs: https://github.com/thundercomb/poetrydb
- Used for: Action 3, finding poems that match the confirmed vibe words
- Key/limits: No key. No rate limit.
- Call: GET https://poetrydb.org/lines,poemcount/rain;3/title,author,lines,linecount
- Real response (trimmed):
  {"title": "Fragments", "author": "Alan Seeger",
   "lines": ["In that fair capital where Pleasure, crowned", ...],
   "linecount": "83"}
- Surprises:
  - Searching lines matches substrings: "rain" returned a poem that only contains "rainbow".
  - Common words like "rain", "night", "love" return 413 (over 500 matches).
  - Word  "nostalgia" return 404; while "energetic" returned only 3 poems.
  - Poems can be very long (83 lines) and contain empty lines.

## Source 2: Last.fm API
- Docs: https://www.last.fm/api/show/user.getRecentTracks
- Used for: Action 1, getting the user's recent songs.
- Key/limits: Free API key, stored in .env (LASTFM_API_KEY). No strict limit stated, but we should avoid many calls in a row.
- Call: GET https://ws.audioscrobbler.com/2.0/
  ?method=user.getrecenttracks&user=rj&api_key=KEY&format=json&limit=5
- Real response (trimmed):
  {"recenttracks": {"track": [
    {"name": "Somebody Told Me",
     "artist": {"#text": "The Killers"},
     "album": {"#text": "Hot Fuss"},
     "date": {"#text": "18 Nov 2026, 22:15"}}, ...]}}
- Surprises:
  - The artist name is under the key "#text", not "name".
  - No genre or mood info, only names, so the "vibe" must come from the LLM reading titles and artists.

## Source 3: Google Gemini API (LLM)
- Docs: https://ai.google.dev/gemini-api/docs
- Used for: Action 2, turning recent tracks into a descriptive, vibe sentence with 3 imagery words, which the user then confirms
- Key/limits: Free API key from Google AI Studio, stored in .env
  (GEMINI_API_KEY). Free tier does have rate limits.
- Call: client.models.generate_content(model="gemini-3.5-flash",
  contents=prompt), where the prompt includes 5 recent songs and
  asks for JSON only
- Real response:
  {"vibe": "A late-night, atmospheric blend of moody R&B and synth-pop
   driven by quiet longing, secret romance, and hypnotic stillness.",
   "words": ["neon", "smoke", "rain"]}
- Surprises:
  - gemini-2.5-flash returned 404 ("no longer available to new users"),
    so model names expire. We list models with client.models.list().
  - gemini-3.8-flash returned 503 (high demand) on two tries;
  - gemini-3.5-flash is the only model that worked. 
  - Asking for concrete imagery words (not moods) gives words that can potentially be searched in PoetryDB.
  
# 5. Data Model (Flora)

| Noun | What it holds | Saved? Why? |
|---|---|---|
| Track | name, artist, album, played_at | No. Asked fresh from Last.fm each time. |
| VibeSummary | username, tracks (the 5 songs used), vibe, words, confirmed | Yes, in vibes.json. Gemini is slow and sometimes returns 503, so if the songs haven't changed we reuse the saved result. It also remembers what the user confirmed. |
| Poem | title, author, lines, linecount, matched_word | Yes, in saved_poems.json, but only poems the user favorites. Search results are asked fresh from PoetryDB. |

Relationships:
- One user's 5 recent Tracks produce one VibeSummary.
- One VibeSummary has 3 words, and each word finds many Poems.
- A user can save many Poems.

# 8. Success Criteria (Gabby)
Code Success:
1. AI successfully looks at user's recent listening history and asks user to approve it's 3 generated words that summarize/are relevant to their music taste before generating poem recommendations. 
2. If unable to find the user's listening history, app prompts the user to sign in, or connect their music account.
3. Users that provide their listening history, and approve of the AI's "vibe words" receive 5 poem recommendations (relevant to the agreed AI description words)

User Success: 
1. 2/3 music-listening university students find their generated music taste "vibe words" to be accurate based off their recently listening. 
2. 2/3 music-listening university students will find at least 3/5 of their recommended poems to be relevant to the "vibe words" they used.

# 9. Priorities and Risks (Flora)
Must-have:
- Get the user's 5 most recent tracks from Last.fm
- Gemini returns a vibe + 3 imagery words
- User can confirm or edit the words (the human check)
- Search PoetryDB with the confirmed words and show poems
- Save vibes to vibes.json
- Handle errors: Last.fm user not found or no history, PoetryDB 404, etc

Nice-to-have:
1. History page: past vibes with their corresponding songs and poems
2. Favorite poems saved to saved_poems.json
3. Backup Gemini model when one is busy

Risks:
1. PoetryDB may return no poems, too many, or poems that are too long.
   - Early test: run 10 to 15 imagery words (neon, smoke, moon, road,fire, ocean...) and count how many poems each returns. If more than 5 return 0 poems, change the Gemini prompt to ask for more common words with examples.

# 10. AI Plan (Flora)
We will ask AI to write the first draft of the Flask routes and the
helper code that calls Last.fm, PoetryDB and Gemini and saves the JSON
files, and to help debug errors. We will write the problem, audience,
data model, success criteria and the main flow ourselves, and we
will write the Gemini prompt ourselves, because the prompt decides what
"vibe" means for our users.

One thing we won't hand off is:
- the final check of whether a poem matches the vibe, because that is
  the human check our depth item depends on.
